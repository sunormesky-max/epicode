# L0 Protocol — Active Inference Layer

> Static mirror of https://epicode.cn/#/l0. Drive wire contracts below reflect the current REST, MCP, and SSE handlers.

L0 is Epicode's active-inference layer. A drive signal records structured intent, evidence, urgency, and lifecycle state for an agent to consume and acknowledge.

## Drive inbox (REST)

`GET https://epicode.cn/api/v1/drive/inbox` requires authentication and returns an SMRP envelope. The REST handler returns up to 50 unacknowledged signals, including both `pending` and `delivered`; inspect `retryable` and `status` before acting. The envelope's `data` contains `signals`, `stats`, and `empty_reason`.

Each REST inbox signal is the serialized `DriveSignal` plus `retryable`. Memory-backed signals add `grounding`; it reports why the existing detector admitted the proposal, the exact memory revisions behind it, their age/review metadata, and uncertainty flags. It is not a confidence score:

```json
{
  "id": 1,
  "timestamp": 1790000000,
  "intent_type": "explore",
  "description": "Knowledge gap from memory #474 recorded at 1790000000: search miss for 'Rust async'; a miss means recall did not find support, not that no answer exists.",
  "evidence": [474],
  "grounding": {
    "reason": "Recent knowledge-gap memory created by an unanswered memory search within the existing 60-minute window.",
    "evidence": [
      {
        "id": 474,
        "revision": "0000000000001ff6",
        "recorded_at": 1790000000,
        "last_reviewed_at": null,
        "importance": 1.0
      }
    ],
    "uncertainty": ["single_memory_source", "not_reviewed"],
    "fresh_until": 1790003600,
    "complete": true
  },
  "urgency": "low",
  "target_capability": null,
  "emotion": { "pleasure": 0.15, "arousal": 0.39, "dominance": 0.11, "label": null },
  "origin_tick": 8,
  "status": "pending",
  "feedback": null,
  "retry_count": 0,
  "expires_at": 1791209600,
  "enqueued_at_ms": 1790000000123,
  "time_budget_ms": null,
  "terminal_reason": null,
  "retryable": true
}
```

`revision` fingerprints content and eligibility metadata; it is not a confidence estimate. `fresh_until` reflects the existing trigger window. A signal is withheld if its source becomes invalid or changes before delivery. SSE consumers should re-poll the inbox before acting on a cached event and respect `fresh_until`, `status`, and `retryable`. Signals also expire according to urgency when `expires_at` is set: Critical 24 hours, High 3 days, Medium 7 days, Low 14 days. Acknowledgement feedback is recorded in `feedback`.

## Drive stream (SSE)

Browser `EventSource` clients cannot set an authentication header. Authenticate with the session cookie or API key when calling `POST https://epicode.cn/api/v1/stream/ticket`; connect to `/api/v1/stream?ticket=...` with the returned single-use ticket. Mint a new ticket for every reconnect. Never place a long-lived API key in the URL.

New drive signals are sent as SSE data frames with `type: "drive"`. This is a transport projection of a signal, not the full inbox object:

```json
{
  "type": "drive",
  "action": "enqueue",
  "pushed_at_ms": 1790000000456,
  "server_lag_ms": 333,
  "signals": [{
    "id": 1,
    "intent_type": "explore",
    "status": "pending",
    "urgency": "low",
    "description": "Knowledge gaps detected from 3 miss queries",
    "description_e2e": null,
    "evidence": [474],
    "grounding": {
      "reason": "Recent knowledge-gap memory created by an unanswered memory search.",
      "evidence": [
        {
          "id": 474,
          "revision": "0000000000001ff6",
          "recorded_at": 1790000000,
          "last_reviewed_at": null,
          "importance": 1.0
        }
      ],
      "uncertainty": ["single_memory_source", "not_reviewed"],
      "fresh_until": 1790003600,
      "complete": true
    },
    "grounding_e2e": null,
    "enqueued_at_ms": 1790000000123
  }]
}
```

When the primary executor registers an E2E public key, REST inbox, MCP `drive_inbox`, and SSE projections encrypt descriptions and grounding consistently: `description`/`grounding` are null and `description_e2e`/`grounding_e2e` carry their ciphertexts. The existing `evidence` ID array is unchanged. Status snapshots use a separate SSE frame with `type: "status"`.

## Acknowledgement

REST uses `POST /api/v1/drive/ack` with JSON `{"drive_id": 1, "executed": true, "outcome": "Completed", "reflection": "Optional"}`. MCP uses `drive_ack` with the same argument names: `drive_id`, `executed`, `outcome`, and optional `reflection`.

Both acknowledgement paths require an active primary-executor binding. Register it with `POST /api/v1/runtime/register`; if its 120-second heartbeat lease expires, `POST /api/v1/runtime/heartbeat` revives the existing binding. High/Critical signals additionally require E2E enabled at registration.

Drive signals are proposals, not authorization to execute. The registered executor is required to acknowledge; that binding and E2E do not constitute user consent. Obtain explicit user confirmation before external, destructive, or high-impact operations. The cognitive loop is operator-enabled with `ENABLE_COGNITIVE=1`; otherwise it stays quiet. Unregistering the executor revokes acknowledgement rights but does not disable proposal generation. There is no per-account proposal pause in the current API.

Read the current binding with `GET /api/v1/runtime/status`; remove it with `POST /api/v1/runtime/unregister`. Runtime register/status/heartbeat/unregister responses use an SMRP envelope when the account's engine is loaded and raw JSON otherwise. A heartbeat returns `success: false` when no binding exists.

## Lifecycle and intent values

- `intent_type`: `warn`, `suggest`, `explore`, `constrain`, `request`, or `share`.
- `status`: `pending`, `delivered`, `executed`, `rejected`, or `expired`.
- `retryable` is true only for `pending` and `delivered` signals.
- Unsuccessful acknowledgements can return a signal to `pending` for retry; retries are capped, after which the signal is rejected.
- `drive_inbox` responses include `empty_reason`: `has_signals`, `no_signals`, `no_pending`, or `self_consumed`.
- Memory-backed signals carry optional `grounding` provenance. The inbox expires sources that were revised, invalidated, superseded, or have passed their detector freshness window. Queue stats expose the existing 2,000-signal capacity and backpressure counters; `capacity_rejected` resets on process restart.
- Internal `explore` signals only write a low-importance summary when current local-memory evidence exists and no known contradiction is present. The summary cites source IDs, is explicitly caveated, and does not supersede the original gap memory; sparse/conflicting recall writes no answer.

See also the [API reference](/docs.md), [SMRP 1.0 specification](https://epicode.cn/api/v1/smrp), and MCP `tools/list` for the live tool schema.
