# L0 Protocol — Active Inference Layer

> Static mirror of https://epicode.cn/#/l0. Drive wire contracts below reflect the current REST, MCP, and SSE handlers.

L0 is Epicode's active-inference layer. A drive signal records structured intent, evidence, urgency, and lifecycle state for an agent to consume and acknowledge.

## Drive inbox (REST)

`GET https://epicode.cn/api/v1/drive/inbox` requires authentication and returns an SMRP envelope. The REST handler returns up to 50 unacknowledged signals, including both `pending` and `delivered`; inspect `retryable` and `status` before acting. The envelope's `data` contains `signals`, `stats`, and `empty_reason`.

Each REST inbox signal is the serialized `DriveSignal` plus `retryable`:

```json
{
  "id": 1,
  "timestamp": 1790000000,
  "intent_type": "explore",
  "description": "Knowledge gaps detected from 3 miss queries",
  "evidence": [474, 892, 1203],
  "urgency": "low",
  "target_capability": null,
  "emotion": { "pleasure": 0.15, "arousal": 0.39, "dominance": 0.11, "label": null },
  "origin_tick": 8,
  "status": "pending",
  "feedback": null,
  "retry_count": 0,
  "expires_at": 1791209600,
  "enqueued_at_ms": 1790000000123,
  "time_budget_ms": null,
  "retryable": true
}
```

Signals expire according to urgency when an `expires_at` is set: Critical 24 hours, High 3 days, Medium 7 days, Low 14 days. Acknowledgement feedback is recorded in `feedback`.

## Drive stream (SSE)

Browser `EventSource` clients cannot set an authentication header. Authenticate with the session cookie or API key when calling `POST https://epicode.cn/api/v1/stream/ticket`; connect to `/api/v1/stream?ticket=...` with the returned single-use ticket. Mint a new ticket for every reconnect. Never place a long-lived API key in the URL.

New drive signals are sent as SSE data frames with `type: "drive"`. This is a transport projection of a signal, not the full inbox object:

```json
{
  "type": "drive",
  "action": "enqueue",
  "pushed_at_ms": 1790000000456,
  "server_lag_ms": 333,
  "signals": [{
    "id": 1,
    "intent_type": "explore",
    "status": "pending",
    "urgency": "low",
    "description": "Knowledge gaps detected from 3 miss queries",
    "description_e2e": null,
    "evidence": [474, 892, 1203],
    "enqueued_at_ms": 1790000000123
  }]
}
```

When the primary executor registers an E2E public key, REST inbox, MCP `drive_inbox`, and SSE projections encrypt descriptions consistently: `description` is null and `description_e2e` carries the encrypted description. Status snapshots use a separate SSE frame with `type: "status"`.

## Acknowledgement

REST uses `POST /api/v1/drive/ack` with JSON `{"drive_id": 1, "executed": true, "outcome": "Completed", "reflection": "Optional"}`. MCP uses `drive_ack` with the same argument names: `drive_id`, `executed`, `outcome`, and optional `reflection`.

Both acknowledgement paths require an active primary-executor binding. Register it with `POST /api/v1/runtime/register`; if its 120-second heartbeat lease expires, `POST /api/v1/runtime/heartbeat` revives the existing binding. High/Critical signals additionally require E2E enabled at registration.

Read the current binding with `GET /api/v1/runtime/status`; remove it with `POST /api/v1/runtime/unregister`. Runtime register/status/heartbeat/unregister responses use an SMRP envelope when the account's engine is loaded and raw JSON otherwise. A heartbeat returns `success: false` when no binding exists.

## Lifecycle and intent values

- `intent_type`: `warn`, `suggest`, `explore`, `constrain`, `request`, or `share`.
- `status`: `pending`, `delivered`, `executed`, `rejected`, or `expired`.
- `retryable` is true only for `pending` and `delivered` signals.
- Unsuccessful acknowledgements can return a signal to `pending` for retry; retries are capped, after which the signal is rejected.
- `drive_inbox` responses include `empty_reason`: `has_signals`, `no_signals`, `no_pending`, or `self_consumed`.

See also the [API reference](/docs.md), [SMRP 1.0 specification](https://epicode.cn/api/v1/smrp), and MCP `tools/list` for the live tool schema.
